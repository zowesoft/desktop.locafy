# Development — desktop.locafy

Verified toolchain and workflow for this repository. The toolchain decision and evidence are recorded in [`decisions/ADR-0002-verified-toolchain.md`](decisions/ADR-0002-verified-toolchain.md).

## Prerequisites

| Tool | Version | Notes |
|---|---|---|
| Go | 1.27.1 (minimum 1.26) | Required by Wails v3 |
| Node.js + npm | 22.14.0 / 11.19.0 | Frontend tooling |
| Wails CLI | v3.0.0 | Command is `wails3` (not `wails`) |
| WebView2 Runtime | 157.x | Preinstalled on Windows 10/11 |

Platform dependencies per OS:

- **Windows:** WebView2 Runtime only (usually preinstalled).
- **macOS:** Xcode Command Line Tools (`xcode-select --install`).
- **Linux:** GTK4 + WebKitGTK 6.0 dev packages (Ubuntu 24.04+ / Debian 13+). Older distributions build with `-tags gtk3` (supported through v3.0.x only).

## Install the Wails CLI

```
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0
wails3 doctor
```

`wails3 doctor` must report no issues before development starts. If `wails3` is not found, add `%USERPROFILE%\go\bin` (Windows) or `~/go/bin` (macOS/Linux) to PATH.

## Project workflow

```
wails3 dev     # development with hot reload; generates bindings into frontend/bindings/
wails3 build   # production build into bin/
wails3 init -l # list available templates
```

## Hot-reload development

```
wails3 task dev     # same as: wails3 dev -config ./build/config.yml -port 9245
```

One session, two reload paths:

- **Frontend** — Vite serves `frontend/` on <http://localhost:9245> and the window loads from it, so edits to React, TypeScript and CSS are applied by HMR with no restart.
- **Go** — the dev watcher rebuilds the binary and restarts the app when a `.go` file changes. Rebuilds are debounced by one second and skip `*_test.go`.

What is watched, and the debounce, live in `build/config.yml` under `dev_mode`. `frontend/` is excluded there deliberately: Vite owns those files, and watching them from both sides causes duplicate rebuilds. `frontend/bindings/` is regenerated by the build step, so a changed Go service signature reaches TypeScript on the next rebuild.

Stop the session with Ctrl+C, which shuts down the app, the Vite server and the watcher together. Use `-port <port>` to change the dev server port; `frontend/vite.config.ts` reads the same value from `WAILS_VITE_PORT`.

Expect the first dev build to take noticeably longer than later ones: it compiles the Go binary with `-gcflags=all=-l`, which bypasses the optimised build cache.

## Verification commands

```
go test ./...    # engine package tests
go vet ./...     # static checks
go build ./...   # compile check
```

All three cover the whole module, including the mobile scaffolding in `build/`. Those directories hold glue that only compiles under the `ios`/`android` build tags and is built as a C archive rather than an executable; `build/ios/main_default.go` supplies the no-op entry point that keeps the package buildable on desktop, so `go build ./...` stays clean without excluding anything. `wails3 build` still handles platform targets itself.

Rules:

- Files in `frontend/bindings/` are generated during build/dev and are never edited by hand.
- Build orchestration lives in `Taskfile.yml`; prefer adding tasks there over ad-hoc scripts.
- Cross-platform builds (per ADR-0001) follow the official cross-platform guide; CI builds and tests on Windows, macOS, and Linux.

## Cross-platform test portability

CI runs the whole suite on Windows, macOS and Linux (the `verify` jobs in `.github/workflows/ci.yml`), so a green local run on one host proves nothing about the others. The Go path helpers follow the host rather than the platform a test simulates, and that has already cost a red run. The patterns to follow:

- **Normalise separators yourself.** `filepath.Base`, `filepath.ToSlash` and `filepath.IsAbs` behave per the GOOS running the test: on Linux `filepath.ToSlash` leaves `\` untouched and `filepath.IsAbs("C:\\x")` is false. A test that simulates another platform's locations (through a seam such as `internal/tools.hostOS`) compares after `strings.ReplaceAll(path, "\\", "/")`, or takes a base name with `strings.LastIndexAny(base, "/\\")`.
- **Assert absolute-ness for the platform under test.** A helper such as `absoluteFor(platform, path)` answers with that platform's rules — drive letter or UNC for Windows, `/` prefix for Unix — and the check also accepts a host-absolute path, because entries derived from the home directory follow the machine running the test.
- **Branch filesystem-layout expectations on `runtime.GOOS`** exactly where the implementation does. `scaffold.VenvPython` returns `.venv\Scripts\python.exe` on Windows and `.venv/bin/python` elsewhere; a test asserting it must choose the same way.
- **Never use pid 1 as an unrelated process-tree root.** Init is an ancestor of every process on Unix, so an ownership walk claims the test process by design. Use a pid out of service (999999); the walk terminates at `current <= 1` and answers false.
- **Read the failing assertion's actual value.** CI prints the host's real output — a path with `/`, a platform's own layout — which is usually enough to see which assumption was Windows-only.

Verifying off-host without CI: pure-Go packages run in WSL (or any second machine) with a user-local Go toolchain and no extra packages. Anything importing `github.com/wailsapp/wails/v3/pkg/application` needs CGO plus the GTK4 and WebKitGTK development packages from Prerequisites — CI installs them on its Linux job only; macOS gets the frameworks from the Xcode Command Line Tools.

## Inspecting the live window

There is no view into the running webview by default. Set `LOCAFY_DEBUG_PORT` to
open WebView2's debugging port on the window:

```
LOCAFY_DEBUG_PORT=9333 ./bin/locafy.exe            # bash
$env:LOCAFY_DEBUG_PORT=9333; .\bin\locafy.exe      # PowerShell
```

`curl http://127.0.0.1:9333/json/list` then lists the page with its
`webSocketDebuggerUrl`, which a CDP client can drive: `Runtime.evaluate` to read
or change state, `Page.captureScreenshot` to capture what the window renders.

This is a browser argument rather than an environment variable because Wails
clears `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` before creating the WebView2
environment. The port stays closed unless `LOCAFY_DEBUG_PORT` is set: anyone who
can reach it can drive the interface, so it is a development affordance and not
a shipped setting.
